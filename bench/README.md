# MeowMeow benchmarks

Load tests for the HTTP server. The harness builds the working tree into a
container image together with the [wrk](https://github.com/wg/wrk) load
generator, starts it, and runs a list of scenarios against it. Only a
container runtime (Docker or Podman) is required; `wrk` on the host is
optional.

```bash
bench/run.sh                     # build, run every scenario, print a table
bench/run.sh --list              # scenario names and what they measure
bench/run.sh -d 30 -c 256 static_64k no_content
python3 bench/report.py compare bench/results/<base> bench/results/<new>
```

## What is measured

Every scenario in `scenarios.tsv` hits one path of `config/routes.conf` with
a fixed number of keep-alive connections for a fixed time:

| Scenario       | Path             | Exercises                                            |
|----------------|------------------|------------------------------------------------------|
| `no_content`   | `/generate_204`  | request parsing, routing and response assembly only  |
| `index`        | `/`              | `DocDir` lookup and a small HTML file                |
| `static_1k`    | `/bench/1k.bin`  | static file smaller than one chunk                   |
| `static_64k`   | `/bench/64k.bin` | static file of exactly one 64 KiB chunk              |
| `static_1m`    | `/bench/1m.bin`  | streaming, 16 chunks                                 |
| `static_16m`   | `/bench/16m.bin` | streaming, 256 chunks, 16 connections                |
| `sendfile_64k` | `/sendfile`      | `Send-File` without the `DocDir` lookup              |
| `headers`      | `/headers`       | eight `Set-Header` rules before the response         |
| `deep_routes`  | `/deep`          | 256 non-matching `Route` blocks before the match     |
| `not_found`    | `/missing`       | the 404 path of `DocDir`                             |
| `abort_418`    | `/teapot`        | the `Abort` directive                                |
| `conn_close`   | `/generate_204`  | `Connection: close`: accept and process spawn per request |

The server runs with `LogLevel 1`; set `MEOW_LOGLEVEL` to measure the cost of
logging. The fixture files and the 256 filler routes are generated by
`fixtures.sh` when the image is built.

All keep-alive scenarios send `Connection: keep-alive` explicitly. The server
closes the connection after any request that carries no `Connection` header
(`parse_http:is_close/1` treats a missing header like `close`, where HTTP/1.1
defaults to persistent connections), and wrk sends none by default. Without
the header every scenario would silently measure one TCP connection per
request, which is what `conn_close` is for.

## Results

Each run writes `results/<label>/` (ignored by git) with:

- `meta.json`: git revision, settings, host CPU, OTP release of the server.
- `<scenario>.json`: wrk's summary (throughput, latency percentiles, error
  counters, responses with an unexpected status) and the server VM's memory,
  process count and reduction counter before and after the run.
- `<scenario>.wrk.txt`: wrk's own output.
- `summary.md`, `summary.json`: the table `run.sh` prints at the end.

`Red./req` in the table is the number of Erlang reductions the server spent
per request. It is a CPU cost proxy that does not depend on the load
generator sharing the machine, which makes it the most stable number for
spotting regressions in the request path.

## Getting comparable numbers

- Use the same `--duration`, `--connections` and `--threads` for both runs
  and let them run at least 10 seconds per scenario.
- Pin server and client to disjoint CPU sets: `--server-cpus 0-3
  --client-cpus 4-7` (the latter needs `wrk` and `taskset` on the host).
- Keep `--network host` (the default). Publishing the port through the
  runtime's forwarder (`--network bridge`) adds a user-space hop with rootless
  Podman and measures the forwarder as much as the server.
- Run the client on the host when `wrk` is installed (`--client host`, the
  default in that case); inside the container it competes with the server for
  the same cgroup.
- `report.py compare` marks changes of 5 % or more. Below that, rerun before
  drawing conclusions.

## Files

| File             | Purpose                                                         |
|------------------|-----------------------------------------------------------------|
| `run.sh`         | driver: build, start, run scenarios, collect, report            |
| `scenarios.tsv`  | scenario list: name, path, expected status, headers, wrk args   |
| `Dockerfile`     | release of the working tree, fixtures, bench config, wrk        |
| `entrypoint.sh`  | `meowbench serve`, `stats`, `shell`, `wrk` inside the image     |
| `fixtures.sh`    | generates `/var/www/bench/*.bin` and `filler.conf` at build     |
| `config/`        | `meow.conf` and `routes.conf` installed to `/etc/nya`           |
| `wrk/report.lua` | wrk script: extra headers, status check, JSON summary line      |
| `report.py`      | `summarize` a run, `compare` two runs                            |

To poke at the benchmark server by hand:

```bash
podman run --rm -it --network host bench.meow.meow shell
# inside: curl -i http://127.0.0.1:8089/generate_204 ; meowbench stats
```
